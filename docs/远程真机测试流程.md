# 远程真机测试流程（无 root，adb shell）

用于 vivo 开放平台等远程真机：没有 root，但有 adb shell。

## 能测什么

- 热点检测准不准：热点开着、关着，模块能不能认对
- 热点设置页的界面：层3 能不能找对热点开关，开着的时候会不会误点
- （可选）层1：这台机型能不能用系统接口开热点

测不了：开机自启、Magisk 模块本身、root 下的层1（非 root 权限少，非 root 开不了不代表 root 开不了）。

## 准备

从仓库拿 3 个文件：

- `RunAuto/sh/lib.sh`
- `RunAuto/sh/diag.sh`
- `bin/hotspotctl.dex`

`diag.sh` 默认只读：不点开关、不开关热点，只会打开热点设置页看一眼再退出。

## 步骤

### 1. 连上设备

adb 是在**你自己的电脑（或手机）上**执行的，云真机桌面上不会有 adb 工具。

平台提供远程 ADB 时（页面上会给一条 `adb connect 地址:端口`，如 Testin 云测）：

1. 电脑上装好 adb（Android SDK Platform-Tools，解压即用）
2. 在电脑的命令行（Windows 用 CMD）执行平台给的 `adb connect` 命令，再执行 `adb devices` 能看到设备就连上了
3. 提示 `failed to authenticate` 时：执行 `adb kill-server`，删掉电脑上用户目录 `.android` 文件夹里的 `adbkey` 和 `adbkey.pub`，再重新 connect

注意：vivo 开放平台的云测真机（dev.vivo.com.cn/vcl）目前不对普通开发者开放远程 ADB，页面和「更多」菜单里都没有入口，「包体上传」只能装 APK。

没有电脑的话，在自己手机上装一个 adb 客户端也行（如「甲壳虫 ADB 助手」，或 Termux 里 `pkg install android-tools`），用同样的地址连接。

不要在云真机里装 MT 管理器之类的终端来跑：那样用的是这个 App 自己的权限，不是 adb shell 的权限，`dumpsys`、`uiautomator` 都用不了，测出来的结果不对。

平台只有网页上的 shell 输入框、没有 adb 地址时：传不了文件，跳到文末「只有网页 shell 时」。

### 2. 传文件

在仓库目录下执行（3 个文件也可以从 GitHub 上单独下载）：

```
adb shell mkdir -p /data/local/tmp/hsp
adb push RunAuto/sh/lib.sh RunAuto/sh/diag.sh bin/hotspotctl.dex /data/local/tmp/hsp/
```

### 3. 热点关着测一次

先在平台画面上确认：屏幕亮着、已解锁、热点是关的。

```
adb shell sh /data/local/tmp/hsp/diag.sh
```

### 4. 热点开着再测一次

在平台画面上手动打开热点（设置 → 个人热点），再执行一次上面的命令。测完手动关掉热点。

平台不让手动开热点的话，可以让脚本用层1 自己开，测完会自动关回去：

```
adb shell sh /data/local/tmp/hsp/diag.sh --on
```

注意：这会真的开热点，部分机型开热点会断开 WLAN。非 root 可能没权限开（结果里 onResult 不是 0），不代表 root 下开不了。

第 4 步会覆盖第 3 步的结果，所以每跑完一次就先做第 5 步把结果取回来。

### 5. 取回结果

```
adb pull /data/local/tmp/hsp/diag_out ./diag_机型_热点关
```

把文件夹（`report.txt` 和 `ui_*.xml`）发给作者。

### 6. 清理

```
adb shell rm -rf /data/local/tmp/hsp
```

## 结果怎么看

| 看 report.txt 里的 | 正常 | 不正常（发给作者） |
|---|---|---|
| 模块判断 | 和实际热点状态一致 | 不一致 |
| 网络共享服务 | 有 / 没有，和实际一致 | 拿不到 |
| WifiManager | 热点开 13，关 11 | 拿不到 |
| 层3 判断（热点关着） | TAP | NONE，或者点的不是热点开关 |
| 层3 判断（热点开着） | ON | TAP（这会把热点点关） |

层3 判断后面的两个数字是要点的坐标，可以在平台画面上对一下是不是热点开关的位置。

## 只有网页 shell 时

传不了文件，就逐条执行下面的命令，把输出复制下来。热点关着、开着各做一遍：

```
getprop ro.vivo.market.name; getprop ro.build.version.release; getprop ro.vivo.os.version
dumpsys tethering | sed -n '/Tether state/,/Upstream/p'
am start -a com.android.settings.WIFI_TETHER_SETTINGS -f 0x10008000
```

等热点设置页打开后：

```
uiautomator dump /data/local/tmp/ui.xml && cat /data/local/tmp/ui.xml
input keyevent 4
```

安卓 10 及以下把 `dumpsys tethering` 换成 `dumpsys connectivity tethering`。

## 选哪些机型测

用户能自己 root 的机型才值得优先测，最好高通、天玑各几台，新老系统都有：

- 高通老机型（骁龙 888 及更早，870 除外）：iQOO Z5、iQOO 7、iQOO 8 / 8 Pro、iQOO Neo5S、vivo X60 Pro+、X70 Pro+
- 天玑：iQOO Neo7 / Neo7 SE、vivo X90、X100 / X100 Pro、iQOO Neo8 Pro、Neo9 Pro、vivo X200 / X200 Pro、iQOO Neo10 Pro

能不能 root 和系统版本关系很大，这个列表是 2026 年 9 月查到的情况，会过时。平台上的机器一般是最新系统，界面可能和 root 用户还停留的旧系统不一样。
